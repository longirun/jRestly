  (216 missed по данным #253) с двух сторон: (a) `handleCacheResponse` —
  post-wire диспетчер RFC 9111 из ADR-0063 (304-revalidation → `update`,
  200/301/404 GET → `put`, unsafe 200..399 → `invalidate`, стриминговый
  streamify синтезированного 200); (b) ветвь `delayMillis <= 0` в async
  retry (`attemptAsync`-рекурсия вместо schedule) — покрывалась до этого
  только «лотерейным» FULL-jitter нулём (1/11) на дефолтной 10-миллисекундной
  политике, т.е. покрытие ветви зависело от соли JVM.
- *Принятый WIP:* `handleCacheResponse` переведён на package-private с
  нормативным комментарием (seam намеренный — unit-тесты ходят по матрице
  без сети); новый сьют `HttpTemplateCacheDispatchTest` (11 тестов,
  `RecordingCache` — записывающий фейк `HttpCache`): pass-through при
  `httpCache == null` / null-аргументах (zero-garbage fast path), 304 →
  синтезированный 200, 304 при вытесненном entry (null из `update` → raw 304
  проходит насквозь), 304 на стриминговом возвращении (re-wrap в живой
  `ByteArrayInputStream` / null-body без streamify), `put` для 200/301/404,
  no-op для 204/302/500, invalidation для POST/PUT/PATCH/DELETE на
  200..399 и no-op за пределами диапазона (199/400/500). Плюс
  `HttpTemplateStreamWireTest.asyncRetryZeroBackoffTakesTheDirectRecursion`:
  `initialBackoff(Duration.ZERO)` → `nextDelayMillis` коротко замыкается на 0
  до розыгрыша джиттера → ветвь прямой рекурсии детерминирована (порядок
  `send-1 → close-failed-attempt → send-2`, 2 отправки).
