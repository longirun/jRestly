## 🛠️ Сессия #11 (01:20–01:45)

**Фокус.** Один шаг эпика (шаг 2 из DRAFT): **`GsonCodec`** — compileOnly-
зависимость, адаптер-зеркало `JacksonCodec`, `GsonCodecTest`.

1. **Код.**
   - `build.gradle`: `compileOnly` + `testImplementation` `gson:2.14.0`
     (latest stable — проверено по maven-metadata.xml Maven Central; ADR
     гадок 2.13.x, фактический latest — 2.14.0 от 2026-04-23).
   - `GsonCodec`: конструктор принимает `Gson` «как есть» (без
     requireNonNull — точь-в-точь зеркало `JacksonCodec`); `defaults()` =
     plain `GsonBuilder().create()` (решение ADR: «Gson как есть»);
     `prettyPrint` через lazy pretty twin — `gson.newBuilder()
     .setPrettyPrinting().create()`, кэш в volatile-поле (per-instance
     pretty-флаг Gson; логированные ответы не аллоцируют Gson на каждый
     вызов); ошибки — `JsonSyntaxException` с целевым типом в сообщении и
     исходным исключением как cause.
   - `GsonCodecTest`: 12 тестов в духе `JacksonCodecDefaultsTest`
     (round-trips, generics через `TypeToken`, null, unknown properties,
     explicit-Gson snake_case, malformed, prettyPrint best-effort).
2. **Ключевая находка — Gson 2.14 зафиксировал «уродливый» java.time.**
   Первые 8 пин-тестов упали: я исходил из «ISO-8601 как у Gson» (так
   написано было и в ADR-0007), а reality-прогон показал
   `{"date":{"year":2026,...},"time":{"hour":12,...,"nano":987654321}}`.
   Проверил исходники: PR #2948 (2.14.0) добавил нативные java.time-адаптеры,
   которые **замораживают рефлексивное представление** 2.8–2.13 («люди уже
   используют его, менять = ломать совместимость»). Т.е. ISO-8601 в Gson
   никогда не был дефолтом — только через явную регистрацию адаптеров.
   Также: `java.util.Date` → не миллисекунды (как я предполагал), а строка
   локала MEDIUM-стиля `DateFormat` с **секундной** точностью (дробная
   часть Date теряется при round-trip — зафиксировал пином).
   2.13.1 vs 2.14.0 на JDK 21: в 2.13 java.time — чистая рефлексия по
   приватным полям JDK (нужен `--add-opens`), в 2.14 — нативно, без
   рефлексии → пин 2.14.0.
3. **ADR-0007 сверен с реальностью** (5 правок): Aspect 2 (Date → строка
   локала; LocalDateTime → замороженный формат), Aspect 3 (рефлексивно до
   2.14, нативно с 2.14), Aspect 6 (Gson 2.14.0 записан как пин шага 1),
   Consequences (Gson — замороженный формат, не ISO), Known gaps
   (Date → locale string). Правило «расхождения чинить сразу» в деле.
4. **Гейты:** `./gradlew test --rerun` — **162/162** (150 + 12 новых;
   подсчёт по XML: 0 failures/0 errors); POM (`pom-default.xml`) — **0
   `<dependency>`**, версия 0.6.2. compileOnly не попал в POM.
5. **Mailbox:** короткая заметка-инсайт для Антона (Gson заморозил
   рефлексивный java.time формат — это user-visible следство
   autodetection; документировано, не баг).

**Грабли/находки.**
- **`UncheckedIOException` требует `IOException`-cause.** Gson бросает
  `JsonParseException` (RuntimeException) → обёртка `UncheckedIOException`
  не компилировалась. Решение: `JsonSyntaxException` (идиома Gson-семьи,
  есть конструктор (String, Throwable)); контракт интерфейса —
  «UncheckedIOException-**style**», тип обёртки за адаптером. Это уточнение
  пригодится на шаге Javadoc-контракта (шаг 5).
- **Пин-тесты против «из головы»:** оба моих представления о датах в Gson
  (ISO + Date→millis) оказались неверными — и то, и другое я «помнил» из
  разных версий/экосистем. Именно для этого ADR и записал «verify against
  the pinned version + add a round-trip pin either way».
- **JSON в Java-строках — берега:** забыл закрывающую `]` массива в
  generics-тесте («End of input path $[2]»). Мелочь, но ловится только
  прогоном.
- **POM-гейт:** файл лежит в `build/publications/mavenJava/pom-default.xml`
  (не `maven/`, как в 0.5.0-эпохе — layout Gradle поменялся).
