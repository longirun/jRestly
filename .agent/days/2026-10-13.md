## 🛠️ Сессия #11 (01:20–01:45)

**Фокус.** Один шаг эпика (шаг 2 из DRAFT): **`GsonCodec`** — compileOnly-
зависимость, адаптер-зеркало `JacksonCodec`, `GsonCodecTest`.

1. **Код.**

     (latest stable — проверено по maven-metadata.xml Maven Central; ADR
     гадок 2.13.x, фактический latest — 2.14.0 от 2026-04-23).
   - `GsonCodec`: конструктор принимает `Gson` «как есть» (без
     requireNonNull — точь-в-точь зеркало `JacksonCodec`); `defaults()` =
     plain `GsonBuilder().create()` (решение ADR: «Gson как есть»);
     `prettyPrint` через lazy pretty twin — `gson.newBuilder()
     .setPrettyPrinting().create()`, кэш в volatile-поле (per-instance
     pretty-флаг Gson; логированные ответы не аллоцируют Gson на каждый
     вызов); ошибки — `JsonSyntaxException` с целевым типом в сообщении и
     исходным исключением как cause.
   - `GsonCodecTest`: 12 тестов в духе `JacksonCodecDefaultsTest`
     (round-trips, generics через `TypeToken`, null, unknown properties,
     explicit-Gson snake_case, malformed, prettyPrint best-effort).
2. **Ключевая находка — Gson 2.14 зафиксировал «уродливый» java.time.**
   Первые 8 пин-тестов упали: я исходил из «ISO-8601 как у Gson» (так
   написано было и в ADR-0007), а reality-прогон показал
   `{"date":{"year":2026,...},"time":{"hour":12,...,"nano":987654321}}`.
   Проверил исходники: PR #2948 (2.14.0) добавил нативные java.time-адаптеры,
   которые **замораживают рефлексивное представление** 2.8–2.13 («люди уже
   используют его, менять = ломать совместимость»). Т.е. ISO-8601 в Gson
   никогда не был дефолтом — только через явную регистрацию адаптеров.
   Также: `java.util.Date` → не миллисекунды (как я предполагал), а строка
   локала MEDIUM-стиля `DateFormat` с **секундной** точностью (дробная
   часть Date теряется при round-trip — зафиксировал пином).
   2.13.1 vs 2.14.0 на JDK 21: в 2.13 java.time — чистая рефлексия по
   приватным полям JDK (нужен `--add-opens`), в 2.14 — нативно, без
   рефлексии → пин 2.14.0.
3. **ADR-0007 сверен с реальностью** (5 правок): Aspect 2 (Date → строка
   локала; LocalDateTime → замороженный формат), Aspect 3 (рефлексивно до
   2.14, нативно с 2.14), Aspect 6 (Gson 2.14.0 записан как пин шага 1),
   Consequences (Gson — замороженный формат, не ISO), Known gaps
   (Date → locale string). Правило «расхождения чинить сразу» в деле.
4. **Гейты:** `./gradlew test --rerun` — **162/162** (150 + 12 новых;

5. **Mailbox:** короткая заметка-инсайт для Антона (Gson заморозил
   рефлексивный java.time формат — это user-visible следство
   autodetection; документировано, не баг).

**Грабли/находки.**

**Фокус.** Один шаг эпика (шаг 3 из DRAFT): **`MoshiCodec`** —
compileOnly-зависимость, адаптер-зеркало Gson/Jackson, `MoshiCodecTest`.

1. **Код.**
   - `build.gradle`: `compileOnly` + `testImplementation`
     `com.squareup.moshi:moshi:1.15.2` (latest stable по maven-metadata.xml;
     moshi-adapters в итоге не понадобился — см. ниже).
   - `MoshiCodec`: конструктор «Moshi как есть», `defaults()` = plain
     `new Moshi.Builder().build()`; ошибки — `JsonDataException` (семья
     Moshi) с целевым типом и origin-cause; prettyPrint — token-for-token
     JsonReader→JsonWriter.
2. **Ключевая находка — «проб moshi-adapters» из ADR оказался фантомом.**
   ADR-0007 гадка `com.squareup.moshi.adapter.JavaTime` в moshi-adapters
   (аналог jsr310). Реальность (проверено по jar 1.0.0/1.5.0/1.14.0/1.15.2
   + upstream tree): `JavaTime` там **никогда не существовал** — артефакт
   содержит только явные адаптеры (Rfc3339DateJsonAdapter для Date,
   Enum/Polymorphic с 1.14). Стандартного java.time-аддона в мире Moshi
   1.x **нет вообще** → проб за убрали, `defaults()` = plain builder,
   java.time/java.util.Date — эскейп-хэтч через explicit Moshi.
   ADR-0007 исправлен (Aspect 2/3/4/6, Consequences, Known gaps).
3. **Вторая находка — plain Moshi отшивает `java.*`-platform-классы:**
   `Moshi.adapter(LocalDateTime.class)` бросает **IllegalArgumentException**
   «Platform class X requires explicit JsonAdapter to be registered» (не
   NoJsonAdapterException, не JsonDataException) — на этапе lookup. Кодек
   ловит `IOException | RuntimeException` и оборачивает в JsonDataException
   с целевым типом (единство с Jackson/Gson: «no adapter» тоже wrap).
   Date — то же самое.
4. **Третья находка — prettyPrint-идиомы Moshi:** `JsonValue` в core нет
   (только интерфейс JsonValueWriter); `Object`-адаптер парсит числа в
   Double (`1` → `1.0`); `JsonWriter.value(String)` **кавит** строку (в
   отличие от Gson/OkHttp-JsonWriter!). Raw-литерал числа — только через
   `JsonWriter.value(BufferedSource)`. Отсюда token-for-token reprint с
   number-fidelity.
5. **Гейты:** `./gradlew test --rerun` — **175/175** (162 + 13 новых);
   POM (`pom-default.xml`) — **0 `<dependency>`**, 0.6.2.
6. **API-грабли (javap по jar, не из головы):** `JsonReader.of(BufferedSource)`
   (okio — moshi его жёсткая зависимость), `JsonWriter.of(BufferedSink)`,
   `setIndent` возвращает void, okio-`writeString` — Kotlin-extension (из
   Java — `writeUtf8`), `Moshi.adapter(Type)` с явным тип-виджем,
   `Buffer` нужен как переменная (writeUtf8 возвращает BufferedSink).

**Грабли/находки.**
- **Меняется концепт эпика на шаге реализации — это нормально.** ADR
  записал «проб moshi-adapters» как данность (зеркалил jsr310), пин по
  jar'ам показал фантом. Правило «сверить с реальностью на шаге, записать

- **Семантика value(String) у разных JsonWriter'ов разная** (Moshi кавытит,
  Gson/OkHttp — raw). Чужие API — только по исходникам/javap.
- **okio в main-коде — ок:** MoshiCodec грузится только после moshi-проба

## 🛠️ Сессия #13 (02:26–02:42)

**Фокус.** Один шаг эпика (шаг 4 из DRAFT): **`JsonCodecResolver`** —
цепочка jackson → gson → moshi + package-private тестовый шов.

1. **Код.**
   - `JsonCodecResolver`: `resolve()` делегирует в package-private
     `static JsonCodec resolve(Predicate<String> classpathProbe)`; цепочка
     jackson → gson → moshi, первое совпадение; fail-fast-сообщение теперь
     перечисляет все три либы (`jackson-databind, gson, or moshi`) + явный
     `jsonCodec(...)`. Адаптеры грузятся только после своего проба (ADR
     Aspect 2).
   - `JsonCodecResolverChainTest` (package `ru.jrestly.json` — первый тест в
     пакете, как планировалось): полная 8-путная таблица комбинаций
     classpath через шов (все три → Jackson; jackson+gson → Jackson;
     jackson+moshi → Jackson; gson-only → Gson; gson+moshi → Gson;
     moshi-only → Moshi; пусто → fail-fast). Функциональные пины
     «defaults() рабочий» для gson-only и moshi-only через общий
     `ru.jrestly.fixtures.TestDto`.
2. **Две грабли Moshi (обе пойманы пином, обе проверены по jar'у 1.15.2):**
   - **Конкретные platform-коллекции отшиваются:** `Map.of("k","v")` →
     `ImmutableCollections$Map1`, plain Moshi: «No JsonAdapter for class ...
     you should probably use Map instead of Map1 (Moshi only supports the
     collection interfaces by default)». По байт-коду
     `ClassJsonAdapter$1.create` (javap): whitelist'а `LinkedHashMap` нет —
     любой platform-коллекционный класс падает в `throwIfIsCollectionClass`.
     Кодек резолвит runtime-class → сериализация Map-значения с defaults()
     не работает. Ушло в ADR Known gaps (user-visible следствие
     autodetection).
   - **Record-доступ:** `private record` внутри теста упёрся в
     `IllegalAccessException` из `RecordJsonAdapter` (v16-вариант в
     multi-release jar'е строит `MethodHandles.lookup()` из
     `com.squareup.moshi` и `unreflect`'ит аксессоры — класс рекорда должен
     быть им доступен). Идиома проекта подтверждена: DTO для рефлексии —
     top-level public (`ru.jrestly.fixtures`), отсюда `Person` в
     MoshiCodecTest и не использовался в plain-Moshi round-trips.
3. **Гейты:** `./gradlew test --rerun` — **182/182** (175 + 7 новых);
   POM (`pom-default.xml`) — **0 `<dependency>`**, 0.6.2.
4. **ADR-0007:** два уточнения — Aspect 6 (шов покрыт
   `JsonCodecResolverChainTest`, 8-путная таблица) и Known gaps (коллекции).

**Грабли/находки.**
- **Multi-release jar'ы: корневой класс — заглушка.** `RecordJsonAdapter` в
  корне jar'а Moshi — stub (методы бросают AssertionError), реальный код в

- **Семь коротких тестов — нормальный размер шага** (вся таблица истины
  цепочки — это и есть спецификация шага, не раздувание).
