### 🛠️ Сессия #296 (хвост Map-prefix fallback — решён: «by design»; 1,644/1,644 в силе)

- *Вход:* хвост из last_session — bare `@RequestParam Map filter` → плоские
  `status=…`, а named `@RequestParam(name="filter") Map` → `filter[status]=…`;
  префикс строится из `rawRequestParamName()`, а не из эффективного имени
  ADR-0017. Варианты: (а) довести fallback (bare ≡ named, TDD) или (б)
  задокументировать различие явно.
- *Исследование:* обе ветки (`createRequestParams` query + `createMultipartParts`
  multipart) читают сырое имя аннотации; скалярный путь — эффективное. Поведение
  записано explicitly в ADR-0017 Aspect 2, в Javadoc `@RequestParam.name()`
  («uses map keys directly») и в README. Оба режима уже e2e-закрыты:
  `GetMethodTest` (плоское `q=java&page=2` / `filter[status]`),
  `RequestParameterFlexibilityTest` (named query Map, bare query Map, bare form
  Map), `MultipartTest` (flat parts / `meta[category]`), `HttpTemplateBuilderTest`
  (unit, оба режима).
- *Решение:* **(б) задокументировать.** Ключевое наблюдение: для Map `name()` —
  не имя параметра, а **опциональный namespace-префикс**: пустой = «без
  префикса», ключи как есть — это индустриальный формат динамических карт
  (Retrofit/Feign `@QueryMap`, Spring `@RequestParam Map` — все шлют bare Map
  плоским). Вариант (а) делал бы плоский режим **недостижимым** (любой Map
  получал бы префикс — явный или по имени Java-параметра) — тихий wire-брейк
  против «strict backward compatibility» самого ADR-0017. Плюс согласованность с
  #212: валидатор осознанно исключает Map из `-parameters`-проверки, потому что
  имена у Map берутся из записей, а не из параметра.
- *Изменения:* README — буллет «Dynamic `Map<?, ?>` parameters» теперь явно
  описывает дефолт (ключи как есть) и контраст со скалярами; ADR-0017 —
  `## Amendment #296` (решение, обоснование, список закреплённых тестов);
  `HttpTemplateBuilder` — комментарии на обоих Map-call-site (код не изменился,
  интент самодокументируем).
- *Гейт:* **1,644/1,644** green (код — только комментарии), javadoc чист под
  `-Werror`.
- *Итог:* «асимметрия» оказалась не багом, а семантическим различием ролей
  одного атрибута по типам: у скаляра `name` — это ключ, у Map — префикс.
  Ключевой ход — проверить, не делает ли «фикс» дефолтный режим
  недостижимым. Хвост #293 закрыт.
- *Дальше:* №7 ждёт А/Б-слова Антона; хвосты: fixtures-javadoc (15 типов),
  Path/File-тела метрик (-1).

### 🛠️ Сессия #300 (свободный аудит HttpTemplate/Redirects — найден и закрыт тихий баг sync 401-refresh failure leg; 1,658/1,658)

- *Вход:* по эстафете #299 — свободный аудит кластера `HttpTemplate`/
  `HttpTemplateBuilder` (зона тихих багов #256–#259), в обход хвоста
  `@ExpectStatus`/`@FollowRedirects` (#207 «фича, не дыра»).
- *Аудит (кандидаты выверены по коду + ADR):*
  1. `isExpectedStatus`: при `expectStatuses != null` allowances
     `conditional`/`optional` не применяются — **by design**: ADR-0023
     Decision 1 явно даёт `@ExpectStatus` «strict precedence», пустой
     список отрезан eager-валидацией (ADR-0004 Amendment #235).
  2. Sync pre-wire `acquire()`/`acquirePermission()` (бросает) vs async
     `tryAcquire(timeout)`/`tryAcquirePermission()` (boolean) — стилистическая
     асимметрия: дефолты интерфейсов (`resilience/RateLimiter.acquire`,
     `CircuitBreaker.acquirePermission`) реализованы через те же
     try-варианты; семантика идентична.
  3. Async 401-refresh `attemptsRef` — порядок CFE верен: `whenComplete`
     (accumulate) регистрируется на `secondPhase` раньше downstream-стадий,
     CFE гонит dependents по порядку регистрации; `attemptAsync`
     `attemptsRef.set(attempt)` (set, не increment) — фазовый счёт,
     аккумуляция cb1 возвращает суммарный.
  4. `Redirects.dropAuthHeaders` null-name safe (`equalsIgnoreCase(null)` →
     false, NPE нет); `nextHop` payload-aware (307/308 сохраняют
     body/parts/boundary/supplier/knownBodySize, GET-downgrade чистит) —
     всё по ADR-0002.
- *НАЙДЕННЫЙ БАГ (кандидат, ставший фактом):* sync 401-refresh —
  аккумулятор первого фазового счёта стоял ПОСЛЕ `executeWithRetries`
  (только success-нога). Если refresh-фаза падала на проводе
  (IOException после исчерпания retry / InterruptedException),
  аккумулятор пропускался и `finally` читал фазовый счёт второй фазы:
  вызов, физически уехавший на провод 2 раза (401 → refresh → connection

  инвариант Amendment #196 «последнее число `onAttemptComplete` равно
  `attempts()`» (второй callback номер 2, attempts() сказал 1). Async
  twin уже суммировал (whenComplete на failure тоже срабатывает).
- *TDD:* red-first `refresh401WireFailureStillSumsBothPhases` (sync,

- *Фикс:* `try/finally` вокруг второй `executeWithRetries` — аккумуляция
  на завершении (success OR failure), точные `whenComplete`-семантики
  async-двойника. Success-нога value-идентична старой. Комментарий в коде

### 🛠️ Сессия #305 (byte[]-скаляр в headers/params закрыт — fail-fast вместо тихого `[B@…`; BRANCH 90.21%; 1,668/1,668)

Главный хвост аудита #301, отложенный в #302/#303/#304 как «нужна отдельная сессия про wire-формат».

- *Карта (все 5 позиций byte[]-просачивания найдены):* `appendHeaderValues`/
  `appendParamValues` явно исключали `byte[]` из array-expansion (`!byte[].class.equals(...)`)
  и фолбэкили в `value.toString()` → под объявленным ключом уезжает `[B@1a2b3c4d`
  — не ошибка, не лог, чистая порча payload'а; то же добиралось до multipart-текстовых
  путей (текстовая часть без contentType + четыре join'а CSV/SSV/TSV/PIPES).
- *Решение (wire-формат ISO-8859-1 / Base64 / fail-fast):* **fail-fast**. Прецедент
  в нескольких местах: «bare byte[] cannot be a multipart file» (запрос L1126),
  fail-fast селекции кодека вместо тихой подмены (#178). ISO-8859-1 навязывал бы
  HTTP-1 семантику заголовков query-ключам и молча пропускал бы искаженные байты;
  Base64 навязывает недокументированную трансформацию; громкий
  `IllegalArgumentException` оставляет решение о кодировании на call-site.
  **Сохранён нарочно:** задокументированный raw-bytes канал multipart
  (`@RequestParam(contentType = "...") byte[]` — ADR-0031/0033) и правила
  file-part'ов не тронуты.
- *Fix (5 точек):* новый приватный хелпер `textValue(value, position)`
  (header/parameter) — fail-fast сообщения с actionable-подсказкой; обе ветки
  append* (акцент: и скаляр, и элементы коллекций/массивов/Map); `createPartFromValue`
  (byte[] без contentType → IAE «нужен явный Content-Type») + 4 join'а multipart-коллекций
  через тот же хелпер. Static fast-path'ы ADR-0055 не тронуты (хелпер —
  только на dynamic-пути).
- *TDD red-first:* 3 теста в `HttpTemplateBuilderTest` (новый интерфейс
  `ByteScalarApi`): header (скаляр/Map-значение/List-элемент), query/form
  (`requestType = APPLICATION_FORM_URLENCODED`), multipart-контракт
  (raw-bytes guard + no-Content-Type fail-fast). Красные ровно по
  «Expected IllegalArgumentException ... nothing was thrown» → зелёные.
- *Документация:* ADR-0017 `## Amendment #305`; javadoc `@RequestHeader` и
  `@RequestParam` описывают byte[]- контракт.
- *Гейт:* **1,668 / 1,668** green во всех 5 модулях (+3, 0 failures/errors),
  javadoc чист под `-Werror`.
- *JaCoCo (пять рекордов подряд):* **BRANCH 3,999/4,433 = 90.21%** (+7 covered),
  INSTRUCTION **98.14%**, LINE **97.79%**, COMPLEXITY **88.39%**; METHOD 1455/1455,
