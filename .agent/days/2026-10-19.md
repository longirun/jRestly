### 🛠️ Сессия #295 (P4: микропроверка статических query в пути → баг-фикс; гейт 1,644/1,644)
- *План:* P4-микропроверка из last_session (кандидат №6, последний кусок ADR-0067).
- *Что проверено:* статическая query в verb-path без `@TargetUrl` всегда
  работала (`createUri` без requestParams → URI как есть; `appendQuery`
  fragment-aware). E2E-кейсы (a) сама, (b) + динамический `@RequestParam`
  (`?size=10&page=2`), (c) + `{id}` (`/items/42?size=10`) — в
  `RequestParameterFlexibilityTest`, все зелёные БЕЗ фикса.
- *Красное:* `@TargetUrl` с query (`?a=1`) + путь с `?size=10` →
  `…/items?size=10?a=1` (двойной `?`; сервер парсит `size=10?a=1` одним
  значением, `a=1` теряется). `URI.create` молчит — тихий баг. Красные:
  `TargetUrlTest.targetUrlWithQueryMergesStaticPathQuery` +
  `targetUrlStaticPathQueryPlusDynamicParamMergesAll` (404, stub
  `urlEqualTo("…?size=10&a=1")` не совпал).
- *Фикс:* `HttpTemplateBuilder.createUrl()` — path query отрезается до
  `joinUrlPath`, сшивается `&`-ом перед query target: `…?size=10&a=1`;
  динамика — последней через `appendQuery`. Порядок: статика пути → query
  target → динамика вызова.
- *Доки:* README — буллет «Static query in the verb path» + уточнение
  Composition-буллета `@TargetUrl`; ADR-0067 — Status + Amendment #295.

### 🛠️ Сессия #296 (хвост Map-prefix fallback — решён: «by design»; 1,644/1,644 в силе)

- *Вход:* хвост из last_session — bare `@RequestParam Map filter` → плоские
  `status=…`, а named `@RequestParam(name="filter") Map` → `filter[status]=…`;
  префикс строится из `rawRequestParamName()`, а не из эффективного имени
  ADR-0017. Варианты: (а) довести fallback (bare ≡ named, TDD) или (б)
  задокументировать различие явно.
- *Исследование:* обе ветки (`createRequestParams` query + `createMultipartParts`
  multipart) читают сырое имя аннотации; скалярный путь — эффективное. Поведение
  записано explicitly в ADR-0017 Aspect 2, в Javadoc `@RequestParam.name()`
  («uses map keys directly») и в README. Оба режима уже e2e-закрыты:
  `GetMethodTest` (плоское `q=java&page=2` / `filter[status]`),
  `RequestParameterFlexibilityTest` (named query Map, bare query Map, bare form
  Map), `MultipartTest` (flat parts / `meta[category]`), `HttpTemplateBuilderTest`
  (unit, оба режима).
- *Решение:* **(б) задокументировать.** Ключевое наблюдение: для Map `name()` —
  не имя параметра, а **опциональный namespace-префикс**: пустой = «без
  префикса», ключи как есть — это индустриальный формат динамических карт
  (Retrofit/Feign `@QueryMap`, Spring `@RequestParam Map` — все шлют bare Map
  плоским). Вариант (а) делал бы плоский режим **недостижимым** (любой Map
  получал бы префикс — явный или по имени Java-параметра) — тихий wire-брейк
  против «strict backward compatibility» самого ADR-0017. Плюс согласованность с
  #212: валидатор осознанно исключает Map из `-parameters`-проверки, потому что
  имена у Map берутся из записей, а не из параметра.
- *Изменения:* README — буллет «Dynamic `Map<?, ?>` parameters» теперь явно
  описывает дефолт (ключи как есть) и контраст со скалярами; ADR-0017 —
  `## Amendment #296` (решение, обоснование, список закреплённых тестов);
  `HttpTemplateBuilder` — комментарии на обоих Map-call-site (код не изменился,
  интент самодокументируем).
- *Гейт:* **1,644/1,644** green (код — только комментарии), javadoc чист под
  `-Werror`.
- *Итог:* «асимметрия» оказалась не багом, а семантическим различием ролей
  одного атрибута по типам: у скаляра `name` — это ключ, у Map — префикс.
  Ключевой ход — проверить, не делает ли «фикс» дефолтный режим
  недостижимым. Хвост #293 закрыт.
- *Дальше:* №7 ждёт А/Б-слова Антона; хвосты: fixtures-javadoc (15 типов),
  Path/File-тела метрик (-1).
