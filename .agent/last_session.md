**Сессия #336: свободный аудит response-decode зоны (срез по эстафете #335) — 2 реальные аллокационные зоны на DTO-ногах `ResponseBody.bufferedOptional`/`bufferedRaw`, ADR-0077, 4 новых теста, гейт 1,822/1,822, рекорд JaCoCo Branch 90.80% удержан по пересчёту.**

1. *Находки (обе на DTO-ногах — самая горячая decode-ветка, INFO включён по умолчанию у JDK-логгера):* (a) codec резолвился **дважды** на DTO-ответ (`codec.get()` в INFO-блоке для prettyPrint + `codec.get()` для deserialize); каждый `get()` в реальном wiring'е = `contentTypeOf` (скан всех headers) + `normalize` (trim/substring/toLowerCase) + линейный скан по всем codec'ам — удвоение даже задокументировано комментом «resolved once per use»; (b) INFO-линия строила `new String(bytes, UTF_8)` — весь пейлоад в temporary-String ради `.length()`; число = UTF-8 **символы**, подписанные «bytes», тогда как byte[]-нога для того же тела отчитывает честный `bytes.length` — «размер ответа» зависел от return-типа.
2. *Фиксы:* (a) один `PayloadCodec resolvedCodec = codec.get()` до гейта, общий для prettyPrint и deserialize — контракт «точно одно резолвинг на ногу, независимо от log-уровня» (lazy-семантика не-DTO ног не тронута — bare-template survival); (b) size-line = `bytes.length` (wire byte size) — второе декодирование тела для лога убрано, prettyPrint получает payload charset как прежде; ASCII-тела — строка байт-в-байт та же. String-нога сознательно не тронута (documented gap: строка и есть return-value).
