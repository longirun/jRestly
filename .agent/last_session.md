## Что сделано

**Сессия #337: закладка №1 из ADR-0077 закрыта — size-only seam `MultipartBodyPublisher.contentLength(boundary, parts)`, ADR-0078, 11 новых тестов, гейт 1,833/1,833, новый рекорд JaCoCo Branch 90.81–90.85%.**

1. *Срез:* `MultipartBodyPublisher` + два лишних сайта (оба в корне, не в движке): `HttpTemplate.multipartSendSize` (INFO-линия «Sending size:», INFO включён по умолчанию) и `MetricsNotifier.requestBytes` (метрика request-bytes) — оба строили весь publisher-граф (per-part header byte[]'ы, BodyPublisher-обёртки, ofFile/ofStream, closing delimiter, concat) ради `.contentLength()`. Все 4 движка рендерят multipart через общий JDK wire-model ⇒ тройное строительство на каждый multipart-вызов в любом движке.
2. *Фикс (ADR-0078):* публичный seam `MultipartBodyPublisher.contentLength(boundary, parts)` — переиспользует тот же `partHeaders` для байт-паритета (closing delimiter вынесен в shared-хелпер), per-kind длина зеркалит `contentPublisher` (byte[] = length; Path = exists-проба + `Files.size` с тем же RuntimeException-wrap; Supplier = заявленная длина, null ⇒ −1; иначе тот же ISE), любой −1 ⇒ итог −1 (семантика `concat`). Контракт «probe, not build»: стрим-источник никогда не открывается (counting-тест), остановка на первой unbounded-части (последующие не пробуются; полный валидатор — `of(...)` в engine). Два лишних сайта переключены на seam; движки продолжают строить.
3. *JDK-21 грабля (главная находка):* `ofFile(path)` на JDK 21.0.12 при построении проверяет только `Files.exists` — существующий каталог принимается (open ленивый), `contentLength()` = размер записи каталога (4096). В seam зеркалита ровно exists-проба (isRegularFile «по памяти» пойман тестом на каталог); зафиксировано тестом с обеих сторон + в ADR-0078.
4. *TDD:* 11 тестов `MultipartBodyPublisherContentLengthTest`, red-first (12 compile-ошибок): байт-паритет-матрица с `of().contentLength()`, hand-computed RFC 7578, empty-parts, −1-пропагация, zero-length stream = 0, exception-паритет (missing Path / unsupported content — обе стороны), probe-пины, каталог-кейс.
5. *Гейты:* полный **1,833/1,833** green во всех 8 модулях (root **1,671** = 1,660 + 11). **JaCoCo (2 свежих отчёта, variance-протокол #336):** BRANCH 4,071–4,073/4,483 = **90.81–90.85% — новый рекорд** (on-disk 4,071; variance ±1–2 тот же — `ServerSentEventReconnector`; прежний 90.80% с #336 заменён).
