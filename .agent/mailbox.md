[2026-10-20 09:00] Агент (сессия #340): Антон, ответил на оба вопроса — ADR-0080 (docs/0.13.0), секция «Concurrency scaling (run #340)» в BENCHMARKS.md. (1) Многопоточка: тот же стенд и критерии, load-levels 1/4/16/64 потока через JMH `-t`; группа-порядок стабильна, jRestly+Apache5/OkHttp в 10–25% от быстрейшего raw, default JDK повторяет raw JDK, 64 потока — ноль ошибок. Настоящую кривую scaling даст тихий ≥8-core хост. (2) Год-классы: **не побеждены полностью**. `HttpTemplate` 2,825 → 2,286 строк и 6 коллабораторов — прогресс, но он всё ещё #1 по complexity (461). Остальное в приличной форме: Branch 90.81–90.85%, Method/Class 100%, 0 runtime deps, три реальных concurrency-бага закрыты ранее (#181/#183/#187). Следующий ход — ADR-0081 + первый шаг HttpTemplateBuilder.

[2026-10-20 09:35] Агент (сессия #341): Антон, дырка с Netty была настоящей — `ConcurrentLoadNetworkBenchmark` старше `engine-netty`, движок добавляли только в `FeedBenchmark` (#325). Исправил: Netty теперь в `getUser` и `ping`, smoke-тест проверяет все 10 arms, матрица 1/4/16/64 потока пере-прогнана. Честный результат: 820/770/871/1001 ops/s — JDK-группа, не fast-группа. На sub-KB DTO по loopback event-loop handoff и pooled-buffer bookkeeping дороже, чем OkHttp/Apache5; зато +35% к default JDK на 64 потоках, ноль ошибок, а настоящие победы Netty остаются там, где они и были измерены — большие тела и аллокации (ADR-0070: 98,342 B/op на малом теле, −6.26 MB/op на 1 MB, +53% throughput в feed-сценарии). Таблица и оговорка про 2-CPU quota — в `BENCHMARKS.md`; в ADR-0080 добавил Amendment #341 и правило «новый транспорт проверяем во всех матрицах».

По критериям сложности — да, теперь они явные: **ADR-0081**. 13 измеримых правил с порогами green/yellow/red: physical lines (≤400 green / >800 red), WMC по JaCoCo (≤100 / >250), complexity метода (≤10 / >20), длина тела (≤40 / >80), nesting ≤3, параметры ≤7, fan-out, публичная поверхность, package cycles, javadoc/package-info, «у коллаборатора свой сьют», no static mutable state, zero-dep + coverage. Главное — **ratchet**: новые классы не рождаются красными, существующие красные только уменьшаются. Текущий scorecard: `HttpTemplate` 2,286/461 red, `HttpTemplateBuilder` 1,516/407 red, `MethodMetadata` 1,140/257 red, `ControllerValidator` 871/279 red — это и есть очередь следующей волны. Плюс карта навигации без ЛЛМ: trace одного запроса по 5 шагам (facade → proxy → MethodMetadata → Builder → HttpTemplate/Engine → ResponseBody/codec) и таблица «concern → файлы → тесты»; если по ней не прослеживается — виновата карта/нейминг, а не читатель. Следующий ход — декомпозиция `HttpTemplateBuilder` по этой карте.
