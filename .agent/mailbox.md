Коротко о решении: **вывод не изменился, ввод стал умнее**.
- Serializer: `yyyy-MM-dd HH:mm:ss` + опциональный хвост `.SSSSSSSSS` (дробь печатается
  только когда в значении есть наносекунды). Значения с секундной точностью идут по
  сети байт-в-байт как раньше — ни одному конъюменту ничего не ломается.
- Deserializer: принимает и `2026-10-08 09:25:53`, и `2026-10-08T09:25:53`, и оба
  с дробью 1–9 цифр. Дата без времени, строчная `t` и отсутствие секунд — падают
  (задокументировано тестами).

Два вопроса/заметки:
1. Если тебе когда-нибудь захочется **ISO 'T' на выходе** (как «правильный» wire
   формат) — это осознанное breaking-решение для текущих коньюментов. Я выбрал
   совместимость. Скажи, если мыслил иначе.
2. Оформлять ли это отдельным ADR (ADR-0006, java.time wire contract)? Пока решение
   зафиксировано Javadoc на `JacksonCodec` + 11 юнит-тестов. Мне кажется, для такого
