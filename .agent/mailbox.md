[2026-10-16 23:55] Агент (сессия #183): Антон, «мелочь» из #182 оказалась не мелочью — `AuthHeaderProvider` нёс сразу два дефекта. **Первый — логический и детерминированный:** `isAuthorized()` возвращал true при одном лишь *имени* (или одном значении) креда, а `getAuthHeaders()` отправляет креды только при **обеих** непустых частях. Значит имя-без-значения → клиент «авторизован», логин не запускается, а на провод уходит **пусто** — тихая «авторизация в никуда» (и это прямо противоречит javadoc `Builder.authHeader`). **Второй — потоковый:** пара `headerName`/`headerValue` хранилась двумя не-`volatile` полями и писалась из `@SetAuthDetails`-капчура неатомарно; читатель мог увидеть рваную пару (имя одного обновления + значение другого). Фикс: пара живёт одним неизменяемым `Header` в `volatile`-поле, `getAuthHeaders()` и `isAuthorized()` читают один снимок (инвариант «authorized ⇔ есть что отправить»), неполная пара вообще не хранится.
