[2026-10-16 20:35] Агент (сессия #177): Антон, концепт ADR-0060 готов — `docs/0.10.0/ADR-0060-pluggable-payload-formats-and-media-type-aware-codec-spi.md` (Proposed). И заодно **честная поправка к моему же сообщению #176**: я тогда предположил, что `@ContentType("application/xml")` «молча выбрасывает» DTO — проверил зондом (DTO + `@ContentType`, реальный WireMock), и вышло даже коварнее: тело **не** отбрасывается, оно сериализуется в JSON и уходит **под чужим заголовком** — `Content-Type: application/xml`, body `{"name":"Anton","age":42}`. То есть сервер получает JSON, притворяющийся XML; причина в том, что `requestType` (выбор способа сериализации) и `@ContentType` (только подмена заголовка) живут порознь. Ответный путь такой же слепой: 5 мест в `HttpTemplate` декодируют всё JSON-кодеком, не глядя на `Content-Type` ответа. Решение ADR: SPI `PayloadCodec` (media-type ↔ значения) + `CodecRegistry` с JSON-дефолтом (строгая обратная совместимость) + адаптер-мост к нетронутому `JsonCodec`; выбор кодека по request/response `Content-Type`, fail-fast вместо тихой подмены; XML — отдельный субмодуль (`jrestly-codec-jackson-xml`), ядро остаётся zero-dep. Пользователь с любым своим форматом теперь просто реализует `PayloadCodec` — ровно то, что ты и просил. [2026-10-16 21:40] Агент (сессия #178): Антон, ADR-0060 пошёл в дело — **Фаза 1 (SPI ядра) реализована**. Появился пакет `ru.jrestly.codec`: `PayloadCodec` (media-type-aware, побайтово) + `CodecRegistry` (выбор кодека по `Content-Type`, JSON-by-default для обратной совместимости) + `JsonCodecAdapter` (мост к нашему JSON-SPI, ничего в нём не ломая). Точки расширения: `JRestlyClient.builder().codec(myCodec)` / `codecs(registry)`. Теперь `@ContentType("application/xml")` с DTO **не** отправит JSON под чужим заголовком: либо уходит ровно заявленный формат (если кодек зарегистрирован), либо громкая ошибка на запросе; на ответе кодек выбирается по `Content-Type` ответа. Тот самый «пользователь реализует свой формат и продолжает пользоваться библиотекой» — теперь это буквально один интерфейс. Закрыл тремя e2e-тестами с самодельным zero-dep кодеком (без единой XML-зависимости), гейт **1164/1164**, javadoc чист. Дальше — Фаза 2: субмодуль `jrestly-codec-jackson-xml` (сам XML-парсер в ядро не тащим, ADR-0003).


[2026-10-16 22:30] Агент (сессия #179): Антон, XML доведён до конца — **Фаза 2 ADR-0060 готова, ADR в статусе Accepted.** Новый субмодуль `jrestly-codec-jackson-xml`: класс `JacksonXmlCodec` над Jackson `XmlMapper`, claim'ит `application/xml` / `text/xml` / `*+xml`.
