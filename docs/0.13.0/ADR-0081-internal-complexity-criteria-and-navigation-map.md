# ADR-0081: Internal-Complexity Criteria and a Navigation Map

- **Status:** Accepted
- **Date:** 2026-10-20
- **Cycle:** 0.13.0
- **Context:** Anton's mailbox question (2026-10-20): "по сложности внутреннего
  устройства и кода. Есть какие-то критерии, а то может там не разберешься
  нигде без ЛЛМ?" This follows ADR-0080, which measured the structural
  scorecard and confirmed that two god classes remain. The answer has two
  parts: (1) explicit, measurable thresholds with a no-new-debt ratchet;
  (2) a reading map that lets a new engineer trace a call without an LLM.

## Decision 1 — measurable criteria, not taste

Every threshold below is computable from the tree and the JaCoCo XML report
(`build/reports/jacoco/test/jacocoTestReport.xml`, generated by the normal
`./gradlew test`). "Complexity" is the JaCoCo `COMPLEXITY` counter (cyclomatic
complexity, the same number used in ADR-0080), so the scorecard and the
coverage report cannot drift apart.

### Size and shape (per class, main sources)

| id | metric | green | yellow (justify) | red (must shrink) |
|---|---|---|---:|---:|---:|
| C1 | physical lines (`wc -l`) | ≤ 400 | 401–800 | > 800 |
| C2 | class WMC (sum of method complexities) | ≤ 100 | 101–250 | > 250 |
| C3 | public methods per class | ≤ 15 | 16–25 | > 25 |
| C4 | outgoing project types (fan-out) | ≤ 15 | 16–25 | > 25 |

### Methods

| id | metric | green | yellow | red |
|---|---|---|---:|---:|---:|
| C5 | cyclomatic complexity per method | ≤ 10 | 11–20 | > 20 |
| C6 | body length | ≤ 40 | 41–80 | > 80 |
| C7 | nesting depth | ≤ 3 | 4 | ≥ 5 |
| C8 | declared parameters | ≤ 5 | 6–7 | > 7 |

### Architecture and public surface

| id | rule |
|---|---|
| C9 | No new package cycle. The single known ring `ru.jrestly` ⇄ `ru.jrestly.http` (ADR-0066) is frozen; new edges must point from transport/feature packages toward the core, never back. |
| C10 | Every package has `package-info.java` with responsibility and key types; every public type/method has Javadoc (enforced by `javadoc -Werror`). |
| C11 | An extracted collaborator is `package-private` unless it is a public SPI, has exactly one responsibility, and has its own test suite (the ADR-0066 lesson: a collaborator without a suite hides missed branches). |
| C12 | No static mutable state on the request path. Shared state must be a `ConcurrentHashMap` cache, an immutable value, or a documented thread-local holder. |
| C13 | Zero runtime dependencies in the core POM; `Method`/`Class` coverage 100%, branch coverage ≥ 90% (ratchet upward only). |

### The ratchet rule (how the criteria are used)

Absolute thresholds alone would either fail forever on the existing god classes
or be ignored. Therefore:

1. **No new red.** A new or newly touched class may not be born above a red
   line; a session that touches an existing red class must lower at least one
   of its C1/C2 numbers (or explicitly record why the step was structural
   only).
2. **Baseline is a ceiling, not a target.** Existing violations are listed in
   the scorecard below and become the work queue. Re-measuring is part of the
   release gate (ADR-0079/0080 practice).
3. **Green is the default for new code.** Only the two known hot spots
   (`HttpTemplate`, `HttpTemplateBuilder`) may stay yellow/red until their
   decomposition waves land.

## Decision 3 — the navigation map (no LLM required)

The map is the contract: if a call cannot be traced with the four steps below,
the missing piece is documentation or naming, not the reader.

### The one-request trace

1. **Entry:** `JRestlyClient.builder()…build()` → `AbstractHttpClient`;
   `client.get(Api.class)` creates and caches a JDK dynamic proxy
   (`AbstractHttpClient.controllers`, `ConcurrentHashMap`).
2. **Declaration → metadata:** `MethodMetadata.of(...)` parses annotations once
   per method and caches the result (`MethodMetadata.CACHE`).
3. **Build:** `HttpTemplateBuilder.build(...)` assembles URL, headers, cookies,
   body/multipart and resilience wiring into an immutable `HttpTemplate`.
4. **Dispatch:** `HttpTemplate.exchange(...)` → cache lookup → rate limiter /
   circuit breaker → request interceptors → `HttpEngine.send(...)` → response
   interceptors → `ResponseBody` (charset, stream/buffer) → `PayloadCodec`
   decode → metrics.
5. **Transport:** `ru.jrestly.engine.HttpEngine` is the SPI; the core ships
   `JdkHttpEngine`, submodules ship OkHttp/Apache5/Netty providers discovered
   through `ServiceLoader` (`HttpEngineResolver`).

### Rules that keep the map readable

- Each package starts with `package-info.java`: responsibility, key types, ADR
  links. Read it before the code.
- Each extracted collaborator has a test class with the same name. The suite
  is the executable spec; if it is missing, the extraction is not finished.
- A method that needs a comment to explain *what* it does is a rename
  candidate; a comment explaining *why* is welcome.
- Public API changes require a Javadoc contract sentence and an ADR amendment;
  internal moves require behavior pins, not new public surface.

## Consequences

- The next structural wave targets `HttpTemplateBuilder` in four steps: URI
  assembly, header/cookie merge, body/multipart assembly, resilience wiring.
  Each step is measured against this scorecard and must shrink C1/C2 without
  touching the public API. Steps (a), (b), (c) and (d) landed as ADR-0082,
  ADR-0083, ADR-0084 and ADR-0085; the builder wave is complete at 779
  lines / WMC 186 / 56 missed branches.
- `ControllerValidator.validateMethod` was split into named check methods
  after the builder wave (C5 target: ≤ 20); ADR-0086 records the extraction
  and the shared `AnnotationChecks` rules. `validateMethod` fell from
  complexity 121 to **3**, and `ControllerValidator` from 871 lines / WMC 279
  to 545 / 130.
- `MethodMetadata` was decoupled in ADR-0090, extracting reflection and
  annotation analysis into `MethodMetadataParser`. `MethodMetadata` fell from
  1,140 lines / WMC 257 / 28 missed branches to **379 lines / WMC 49 / 0 missed branches**,
  permanently exiting the RED god-class list.
- Future release gates report the same table (lines/WMC/missed branches) next
  to JaCoCo percentages, so structural debt is visible in every cycle.
- Next free ADR: **0091**.
